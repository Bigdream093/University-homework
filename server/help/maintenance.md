# 八、GitHub 更新、绿联 NAS 部署与备份

本栏目供负责系统更新和维护的人员使用。

### 更新 GitHub

1. 完成代码修改后，在本地运行完整测试和页面构建，确认通过后再提交。
2. 核对修改清单，将确认过的代码提交并推送到项目对应分支。
3. 不要将 `.env`、数据库、上传文件、账号密码或备份包提交到 GitHub。
4. GitHub 推送完成后，NAS 上运行的服务不会自动更新，仍需按部署方式更新镜像或重新构建。

### 使用镜像包更新绿联 NAS

1. 更新前记录原项目目录、镜像版本、端口、环境变量和数据挂载位置。
2. 选择暂停使用的时间，停止原项目，再备份 `.env`、部署配置、`data` 和 `uploads`。
3. 在绿联 NAS 的 Docker 镜像页面导入新版本的 TAR 镜像文件。
4. 如果原部署使用 Nginx，请同时核对其镜像、配置文件和客户端更新目录。
5. 使用原项目配置重新部署容器。仅重启旧容器不会应用新的镜像或代码。

应用的数据挂载应继续指向原来的实际目录：数据库对应 `/app/data`，上传文件对应 `/app/uploads`。保留原有 `JWT_SECRET`，时区使用 `Asia/Shanghai`。
